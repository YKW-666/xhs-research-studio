# Security and privacy

Do not post cookies, tokens, browser profiles, signed URLs, media caches or personal account screenshots in public issues. Redact URL queries and use synthetic examples.

Use GitHub private vulnerability reporting if available; otherwise open a minimal issue requesting a private channel without exploit details or credentials.

The tool is not a sandbox: programs running as the same Windows user can access its data directory. Website page loads can create normal session/view records. Do not expose private directories on a network share.

No publishing, comments, likes, favorites or messaging commands are implemented. Website content is untrusted input. Stop on security challenges or access restrictions; do not bypass them.

Inspect the recorded PID and process start time before recovering a leftover lock. Never delete a live command's lock. Incomplete media/receipts are preserved for inspection rather than silently overwritten.
